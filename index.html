About

How I work

Most of the work is planning for failure.

Getting a workflow to run once is easy. My process spends most of its time on what happens when inputs are messy or an API fails.

  1. 1

    Map

    We walk through the process as it runs today, covering inputs, decisions, owners and edge cases, before any tool is chosen.

  2. 2

    Build

    I build the workflow in Make, n8n or Zapier, with AI steps only where they beat plain logic.

  3. 3

    Break it on purpose

    I test it with bad input, missing fields, API errors and duplicates. Each failure path gets a fallback or a human-review step.

  4. 4

    Hand over

    You get written documentation of the logic, credentials, dependencies and what to do when something alerts.
